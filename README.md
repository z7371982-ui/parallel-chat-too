# 并行对话 0.6.8-r3

## 本次更新：切换状态连续显示、缩短接回等待

仍采用 0.6.8 的单页面后台接收与原生回放方式。保留 r2 的三会话流式切换、代理联动和侧边条功能。

- 悬浮面板按实际网络任务判断是否还在生成，不再因酒馆释放当前前台而短暂显示待命、减少正在回复数量。
- 面板重绘时保持头像转圈的进度，避免所有头像一起跳回起点，看起来像暂停。
- 底部发送/停止按钮在交接阶段暂时显示转圈和“切换中 · 后台继续生成”或“接回中”提示，接回后恢复原生按钮。提示准确区分界面交接与后台生成；没有篡改酒馆忙碌标志或屏蔽原生停止事件。
- 接回的固定调度等待从 400ms 降为 50ms；提示词试算完成后主动唤醒。页面可见时，保存/收尾未完成的检查间隔从 800ms 降为 150ms，仍等实际收尾结束才接回。页面隐藏时保持原有较慢检查。

## 关于实时写入

后台文字一直实时接收。完整写进酒馆聊天，仍需切回后经过酒馆原生解析、消息处理和保存；本次没有改成后台直接写聊天文件。长回复、平滑流式显示及其他扩展处理仍可能带来接回停顿，不能保证零延迟。真正让三个非当前聊天都独立完成原生处理和保存，需要改变写入机制或使用独立页面，超出了此次保留单页面运行方式的范围。

## 安装与验证

先等旧版本所有生成、保存及后台回复写回完成，备份原扩展目录，然后用本包全部文件覆盖原 0.6.8 分支，刷新确认版本 0.6.8-r3。同一个酒馆只启用一个并行扩展。

Chromium、Windows WebKit 的本机模拟测试覆盖：三路生成反复切换、各自保存、生成图标连续显示、真实完成/停止状态、底部交接提示清除、保存等待与超时恢复，以及原代理/侧边/存储回归。模拟环境下页面就绪至接回启动从约 417–418ms 降到约 70ms；这是特定模拟场景，不能代表手机实际耗时。没有完成用户设备的实机测试。

以下为 r2 及更早版本记录。

## 本次更新：三个会话生成中切换查看

继续使用 0.6.8 单页面方式：三个会话可以同时保留生成请求，切走继续接收，切回把已收到的内容和后续流交给酒馆显示。切换不会重新请求模型，也没有新增独立酒馆 iframe。0.5.6-r2 独立窗口分支本次未修改。

- 修复正在接回后台流时再次切换被直接拒绝的问题：保留点击目标，等当前交接完成后自动切换，不必等整条回复生成完。
- 连续选择不同会话时保留最后一次选择，按顺序完成安全交接，不同时改动酒馆的当前聊天。
- 原生角色列表在接回准备、保存和切换期间也使用相同的切换协调，避免准备回放时被另一次角色切换打断。
- 酒馆可能先恢复发送按钮、再执行消息处理和保存；现在等待这次原生收尾结束后再换聊天，避免回复或后处理落入其他会话。异常收尾超过等待时间时保留请求和原聊天；收尾完成后仍能恢复。
- 旧回复尚未接回时，阻止额外发送/继续/重新生成/右滑生成落入未接管的请求；草稿保留，仍可选择其他会话。此保护不替代三会话流式切换。
- 沿用 r1 的代理预设/地址/密码联动、侧边条和存储提示。

切换遇到酒馆正在组装提示词、接回或保存时会短暂等待交接，已有网络请求持续接收；无需等待模型输出整条完成。这里的“后台”指同一页面内其他会话，手机锁屏或系统暂停应用仍受系统限制。

## 0.6.0 改了什么（重写）

0.5.x 每打开一个会话，就在 iframe 里再启动一整个酒馆（完整页面、全部扩展、角色库）。两三份酒馆同时运行的内存占用在部分手机（尤其 iPhone / TauriTavern）上会超过系统给 WebView 的上限，表现为「添加角色卡时闪退或整页重载」。这是结构造成的，减载无法根治。

0.6.0 起不再创建 iframe，全程只有一个酒馆页面：

- **转入后台**：生成进行中切换对话时，酒馆一侧按「停止」收尾，但真正的网络请求不取消，由扩展继续接收并保存响应。
- **切回写入**：回到那份聊天后，扩展让酒馆走一次原生的重新生成 / 继续 / 滑动，并把保存下来的响应原样交给它。不会再次请求 API，正则、变量脚本、保存都是酒馆原生逻辑。
- 回复还没收完就切回，会接着实时显示。
- 扩展不自己拼提示词，不直接写聊天文件，不保存 API 密钥。

额外占用只有后台回复的文本本身，和开几个角色无关。

## 功能

- **多会话并行**：不同角色，或同一角色的不同聊天记录。每次请求用发出当时的预设 / API / 模型，所以三个会话可以各用各的。
- **悬浮管理**：查看状态、切换、停止后台生成、丢弃或复制回复、关闭会话。可开启「点击悬浮头像切换对话」（默认关闭）。
- **完成提醒**：后台回复完成后在对应头像上显示角标并播放提示音（可关）。
- **侧边收起**：悬浮入口拖到屏幕边缘再向外滑，缩成小条；黄色表示生成中，绿色表示有回复待查看。
- **显示设置**：浅色 / 夜间模式；可在扩展设置里隐藏悬浮入口。
- **历史对话选择**：「打开对话」默认进入角色最近的聊天，「其他对话」可选指定历史。搜索列表带头像，按最近聊天排序。
- **角色配置记忆**：按角色记住预设、模型与原生代理配置，切到该角色时恢复（可关）。
- 生成中直接点酒馆自己的角色列表，也会先转入后台再切换。

## 使用上的区别与限制

- 同一时间只显示一份聊天；切换会话就是酒馆原生的切换聊天。阅读位置会恢复，但页面内的临时状态（展开的折叠、没保存的编辑等）不保留。
- 转入后台时，聊天里会先留下已经收到的半截回复；切回后替换成完整内容。监听生成事件的扩展会先看到一次「停止」，切回时再看到一次完整生成。
- 回复写回要等你切回那份聊天。没切回之前，完整回复保存在本设备的浏览器存储里（刷新后仍在）；还没收完的回复在刷新、退出或系统回收页面时会中断。
- 切回时聊天末尾如果已被改动（比如在别的设备上继续聊了），不会自动写入，可在面板里复制文本或丢弃。
- 不支持：群聊、扩展自己发起的请求（总结、生图提示词等）、Horde、带工具调用的回复。这些照常走原生流程，只是不能转入后台。
- 最多 3 个会话，每个会话各自可以有一条回复在生成。

## 验证范围

在 SillyTavern 1.19.0（桌面 Chromium，含手机视口）上用模拟的 OpenAI 兼容接口实测通过：普通发送、重新生成、滑动、继续四种类型的中途切走与切回；首字到达前切走；未收完时切回续播；非流式；接口报错；切回时流式开关已变化；刷新后恢复已完成的回复；后台停止并保留已收到部分；生成中点击原生角色列表。回放过程中没有产生额外的 API 请求。

**尚未在 TauriTavern 和 iPhone 真机上测试。** 新版只依赖页面的 `fetch`、酒馆的公开上下文接口和几个原生按钮，不依赖宿主的启动流程，但 TT 的请求转发层是否完全兼容需要真机确认。Claude / Gemini 原生格式和文本补全接口走的是同一条「原样回放」路径，未逐一实测。
